Pro 工程接入与版本检查 ​

返回开发专家 使用 Agent 组合 Pro 组件时，先确认项目安装包和资料包的配对关系，再选择字段、列表、编辑、详情或模板配方。基础组件的 文档 MCP 与本地 Pro 专家资料分别使用，不以相同版本字符串推断所有能力都可运行。

从需求发现能力 ​

在配套本地专家工具中，用 agent_discover 按意图、符号或标签查询，再用 agent_read 读取返回的实际 ID。按需选择 API、示例、配方、迁移或来源部分，并使用分页参数读取完整结果。

json
{ "query": "AsamCrudPage" }

不要猜测能力 ID。资料提及某个符号，并不保证项目实际安装包已包含该运行导出；仍需检查公开 exports、类型、样式和必要的 peers。

接入现有工程 ​

沿用项目已有导入方式，保护现有配置、业务代码和数据 provider。组件只从正常包的公开入口导入；按包说明引入 Element Plus、UI 和 Pro 样式，不用源码别名替代安装包。

先把字段模型、空值、转换和校验规则列清楚，再组合查询、列表、编辑与详情控制器。0、false、空串、null 和缺省值按各自业务含义处理。请求、租户、权限和业务服务由应用提供。

可从 高级组件目录 查看真实组合示例及完整源码，再将本地示例数据替换成业务接口。

选择配方 ​

Pro 资料 按场景组织字段、表单、表格、应用能力和页面模板。配方用于指导增量修改；具体属性、事件、插槽及实例方法以对应组件页和实际安装包声明为准。

网页中的具名迁移方法可能尚未进入当前离线资料包。工具查不到时，按网页说明和实际安装包进行人工适配，不将文档中的方法冒充工具已经自动完成。

截图需求应先读取图片；可交互 demo 应先实际打开并操作。区分可见布局与未表达的行为，说明正常、空、错误及加载状态，随后保存普通 Vue 源码并验证真实效果。

验证与修改 ​

agent_inspect、agent_diagnose 用于检查显式指定的工程和文件，agent_validation_plan 用于读取验证计划。资料查询和只读计划本身不会替应用执行任意工程命令或修改产品代码。

类型检查、构建、源码审查和适用的运行验证由已获授权的宿主执行。需要实际修复时，先明确允许修改的文件、已有用户改动和必须保留的断言；修改后检查真实行为，未执行的内容保留为未验证。

迁移边界 ​

查询迁移资料后，核对明确支持的输入格式和目标版本。某个具名配方支持的旧模型，不代表任意历史工程都能自动改写。未知版本、未知格式及不支持的自动改写应明确停止，改用已说明的人工适配流程。

资料更新、组件更新和宿主工具更新分别核对；更新知识目录不会自动替换项目已安装的组件包。
