Card List ​

Example data, control text, messages and source comments may be in Chinese. Viewer controls and API headings use English. Untranslated API descriptions are marked.

AsamCardList lays out the cards in its default slot in a grid or masonry layout. The caller manages data loading, pagination, and selection. Use AsamCard or AsamTaskCard for the card content.

Set cardSize to small, default, big, large, or a custom object of the form { minWidth, maxWidth?, minHeight?, padding?, titleFontSize?, bodyFontSize?, contentGap? }. Numeric values are in pixels. Card dimensions are independent of control size. Explicit values for the legacy minCardWidth and maxCardWidth take precedence, followed by the new maxWidth. Omit cardSize to preserve the legacy tokens. When you supply explicit dimensions, the maximum width is unlimited by default. With columns='auto', the layout fits the parent container automatically. A numeric column count divides the parent width evenly.

With layout='masonry', cards use their natural heights. DOM order and keyboard navigation follow the data order. The layout batches measurements after changes to images, fonts, content, or the container, and recalculates when it becomes visible again. SSR and hydration initially render a regular grid. Switching layouts preserves card instances and focus. During reflow, the layout preserves the scroll anchor of a visible or focused card and skips scroll compensation if the user or browser has already scrolled. Reflow has no position animation and happens immediately with reduced motion enabled as well. Masonry ignores equalHeight. Give each card a single root element and avoid overriding its root grid-row or grid-column or forcing a percentage height.

Automatic widths and fixed columns ​

The example uses a separate card component and data file. Switch layouts to compare automatic widths with a three-column grid, and toggle equal height to see how cards with different amounts of content behave.

A positive integer for columns fixes the number of columns. Omit it, pass null, or pass an invalid column count to use automatic layout. In automatic mode, minCardWidth and maxCardWidth control card widths, and a single card stays within the container. In fixed-column mode, the columns divide the available width evenly.

Spacing and alignment ​

Widths and gaps accept numbers or CSS length strings. Numbers are treated as pixels. Omit these values to use the card layout tokens. rowGap inherits gap when omitted. align accepts start, center, or stretch. equalHeight is enabled by default.

In automatic mode, if both widths are numbers or pixel strings and the minimum exceeds the maximum, the maximum is set to the minimum. The component only compares widths it can resolve in pixels, so provide a valid, consistent range when using other CSS units. Avoid forcing too many columns in a narrow container.

Usage constraints ​

The component exposes a default slot only. It has no list events or instance methods. Set spacing and card widths through the layout props. Keep control size and data-table pagination on their respective components.

Usage and API notes ​

Fixed columns, automatic widths, and invalid ranges ​

A positive integer for columns fixes the column count. null, zero, negative numbers, and non-integers select automatic layout. If minCardWidth exceeds maxCardWidth and both are comparable in pixels, the maximum is clamped to the minimum. Numeric gap values are converted to pixels, an omitted rowGap inherits gap, and a blank string uses the token default. align controls horizontal alignment. equalHeight is enabled by default and stretches every card in a grid row to the height of its tallest card. When disabled, cards align to the start vertically and keep their natural content height and minimum height. These settings are independent. When automatic layout becomes a single column, each row contains one card and can have a different height.
