Quick start ​

Install and style ASAM UI Pro in an existing Vue project, then render your first component. See versions and migration for package pairing and migration guidance.

1. Install UI and Pro ​

Install UI 2.0.1 and Pro 2.0.1 from npm. Pro declares an exact peer dependency on this UI version.

The matching UI package uses Tiptap 3.31.3. Before creating a pnpm 11 lockfile, merge these overrides into your pnpm-workspace.yaml. They keep the Vue adapter's two optional extensions on the same version as its core and pm dependencies. Full project downloads already include these overrides.

yaml
overrides:
  '@tiptap/vue-3@3.31.3>@tiptap/extension-bubble-menu': 3.31.3
  '@tiptap/vue-3@3.31.3>@tiptap/extension-floating-menu': 3.31.3
sh
pnpm add @asam-ui/ui@2.0.1 @asam-ui/pro@2.0.1 vue@3.5.34 element-plus@2.14.7

This release requires Vue >=3.5.34 <3.6.0 and Element Plus 2.14.7. Add any missing dependencies to your project.

2. Import styles ​

Import the styles in this order in main.ts:

ts
import 'element-plus/dist/index.css';
import '@asam-ui/ui/style.css';
import '@asam-ui/pro/style.css';

If your app already loads Element Plus styles, keep a single import before the ASAM styles. When using the component resolvers, avoid duplicate style imports.

3. Render your first component ​

Put this in App.vue and let the existing entry point mount the app:

vue
<template>
	<AsamApplicationProvider>
		<AsamDisplayCard title="Your first Pro page">Start organizing your page here.</AsamDisplayCard>
	</AsamApplicationProvider>
</template>

<script setup lang="ts">
import { AsamApplicationProvider, AsamDisplayCard } from '@asam-ui/pro/components';
</script>

4. Check the app ​

Run the existing development script. If it is called dev:

sh
pnpm run dev

Open the local address printed in the terminal, confirm the card renders, then run the project's type check and build. Follow the component documentation when wiring reads, permissions, or saves. See application capabilities for lifecycle, session, and persistence contracts.

Configure advanced options when needed ​

Pro groups its public API into components, application capabilities, and page templates. For application services, use @asam-ui/pro/application/navigation, security, preferences, or transport. Composables are available through @asam-ui/pro/application/composables and individual entry points.

ts
import { Application, Components, Templates } from '@asam-ui/pro';
import type { Types } from '@asam-ui/pro';
import { useToggle } from '@asam-ui/pro/application/composables/use-toggle';
const [opened, toggle] = Application.composables.useToggle(false);

Types is compile-time only. Category and exact imports share the same implementation. Prefer a direct entry point for an individual composable when you need to limit dependency resolution. The type dictionary identifies public types.

For dark mode, also import the Element Plus dark variables and configure the application theme preference:

ts
import 'element-plus/theme-chalk/dark/css-vars.css';

Auto-import configuration ​

If your project already uses Vite auto imports, add the ASAM resolvers to your existing configuration. Install any missing optional plugins in the consuming project.

ts
import Components from 'unplugin-vue-components/vite';
import AutoImport from 'unplugin-auto-import/vite';
import { AsamUIResolver } from '@asam-ui/ui/resolver';
import { AsamProResolver, asamProAutoImports } from '@asam-ui/pro/resolver';
const plugins = [
	Components({ resolvers: [AsamUIResolver(), AsamProResolver()] }),
	AutoImport({
		imports: asamProAutoImports({
			include: ['Application', 'useToggle', { name: 'useClickAway', as: 'useOutside' }],
			types: ['UseCountDownOptions']
		})
	})
];

You can restrict the composables with an option such as abilities: ['preferences', 'composables/use-toggle']. The resolver imports only public components and their styles. Functions use direct imports by default, and type entries generate type-only imports.
