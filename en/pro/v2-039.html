Data entry and step-by-step forms ​

Choose a single-page application form, a three-step form, or a grouped form with nested rows. Each template is a complete editable Vue page with local examples of validation, saving, and recovery.

Use and API ​

Start with BasicFormPage.vue, StepsFormPage.vue, or AdvancedFormPage.vue and their shared source. Supply a typed identity and FormServices for reads, validation, writes, and verification. Keep one operation ID when the outcome of a write is unknown. The host can provide a DraftAdapter for persistence across reloads.

See usage and customization and the page and service API. The source archive preserves the original code and comments.

Reference ​

API and behavior

Page props, events, and methods ​

FormPageProps requires identity: { scope, entity, version } and services: FormServices. Optional props are disabled, readonly, size, configurationVersion, and session. The step-by-step page also accepts draftAdapter. Both access flags default to false. Size defaults to default and the configuration version to '1'.

Changing identity or configuration version invalidates the old session. Replacing services retains the active coordinator and pending operation ID where applicable. A borrowed session must match the page, identity, and services. Supply a replacement borrowed session after a configuration change. The host owns disposal.

The saved(receipt: FormReceipt) event fires once for a confirmed outcome of the current operation, whether confirmed by submission or verification. cancel() closes the current display. Edit the SFC directly to customize its layout. The page exposes reload(): Promise<void>, submit(): Promise<boolean>, verify(): Promise<void>, and cancel(): void. Submit resolves to true only when the service confirms the write for the current session.

Services ​
Method Input Outcome
load FormRequest with page, scope, entity, version, and signal A found model or an empty state. On error, offer retry.
validate Converted DTO and FormRequest Read-only AsamEditIssue[]
submit DTO and FormWrite with operation ID success, failure, or unknown
verify Original FormWrite success, not-applied, or unknown
departments Region and FormRequest Departments for the active region and identity

A receipt must match the original operation ID, entity, and version. An invalid or mismatched receipt is treated as unknown. Services receive independent request snapshots. The session rechecks the active identity and write permission immediately before calling the service, and ignores late results that target another entity. The coordinator retains the outcome of an already dispatched write. Read-only access allows reading and verification. Both read-only and disabled access prevent a new write.

Form models and session ​
  • The basic form uses BasicInputModel and BasicSubmitDto. The step-by-step form uses StepsInputModel and StepsSubmitDto. Convert and validate input before calling the service. Resource values map to stable IDs. Preserve explicit empty values and missing properties.
  • The step-by-step form validates the current step to advance and validates all steps before submission. A field error returns the user to its step. An unkeyed error appears in the summary. Draft reads and writes happen only through the explicit controls.
  • The advanced form uses AdvancedModel and AsamSchemaSubmitModel<AdvancedModel>. Keep row keys stable and allow numeric zero and string zero to coexist. The department follows the clear-on-change policy. A hidden contact note is retained locally and omitted from submission, a hidden keepNote is retained and submitted, and a hidden clearNote is cleared and omitted.
  • createFormPageSession(config) exposes session state, an editor view, receipt and operation identity, and methods for opening, updating, submitting, verifying, cancelling, reloading, and restoring a draft. Calling dispose() releases session-owned state and listeners. The host retains borrowed coordinators and services. A registered page validator is removed when that page exits.
  • Explicitly retry an unknown write only after verification reports not-applied. The session checks authorization immediately before calling the service, including when invoking a page method directly.

Usage

BasicFormPage.vue, StepsFormPage.vue, and AdvancedFormPage.vue are complete editable pages. App.vue provides three hash routes and local scenarios. The example loads the Element Plus, UI, Pro, and page styles in that order.

Page Structure Initial fields Shared building blocks
Basic Single-column application with a summary and a confirmed result 12 fields Field modes, DTO conversion, and write coordination
Step-by-step Three steps with a persistent summary and draft guidance 5 fields per step AsamStepsForm, field conversion, and coordinated saving
Advanced Profile, finance, contact, policy, and line-item groups 20 fields plus 5 rows of 2 fields AsamSchemaForm, nested schema, and write coordination

The local service simulates a 100 ms read, 40 ms validation, and 100 ms save or verification. Each session has its own in-memory state. The scenario preserves distinct values such as numeric zero, string zero, false, an empty string, null, and a missing optional property. CNY amounts use yuan with two decimal places, dates use calendar strings, and resources submit stable IDs.

Customize a form ​
  1. Edit the basic layout in BasicFormPage.vue. Adjust basicBindings and modesFor in Models.ts to change field and DTO mappings, and use Validation.ts for rules.
  2. Define each step using stable IDs and field keys in Models.ts. Assign a field to one step and validate it with validateCurrent in StepsFormPage.vue. Final submission goes through createFormPageSession.
  3. Define nested fields with createAsamNestedSchema<Model>().field in AdvancedSchema.ts. For repeated rows, use a stable business key and update the model and initial values in Types.ts and Models.ts.
  4. Implement FormServices for loading, validation, submission, verification, and department lookup. Verify an unknown write with the original operation ID. Use the example's save-error and unknown scenarios to see the recovery flow.
  5. Add an explicit DraftAdapter for persisted drafts. Validate the asam-forms-draft-v1 format, page, scope, entity, and version, and honor the abort signal. The default draft stays in the current session.
  6. If you pass a host-owned session, create it through createFormPageSession and match the page, identity, and services. The host owns permissions and eventual disposal.

The three pages use distinct layouts and share ASAM controls and tokens. Reduced motion disables the short result transition.

Types.ts · Type source

import type { createFormPageSession } from './Session.js';
import type { AsamControlSize } from '@asam-ui/ui';
import type { AsamValue } from '@asam-ui/ui';
import type {
	AsamEditIssue,
	AsamFieldModel,
	AsamWriteCoordinator,
	AsamFieldViewBinding
} from '@asam-ui/pro';
import type { AsamMoneyInputValue, AsamMoneyPayload, AsamResourceValue } from '@asam-ui/pro';

export interface BasicInputModel {
	name: string;
	code: string;
	quantity: number | null;
	budget: AsamMoneyInputValue;
	date: string | null;
	category: AsamValue | null;
	enabled: boolean | null;
	tags: readonly AsamValue[];
	note: string;
	nullable: string | null;
	optional?: string;
	resource: AsamResourceValue;
}
export interface BasicSubmitDto extends Omit<BasicInputModel, 'budget' | 'resource'> {
	budget: AsamMoneyPayload | null;
	resourceId: string | number | null;
}
export interface StepsInputModel extends Omit<BasicInputModel, 'resource' | 'optional'> {
	region: string;
	department: string | null;
	contact: string;
	email: string;
	confirmed: boolean;
}
export interface StepsSubmitDto extends Omit<StepsInputModel, 'budget'> {
	budget: AsamMoneyPayload | null;
}

export type FormPage = 'P06' | 'P07' | 'P08';
export interface FormIdentity {
	readonly scope: string;
	readonly entity: string;
	/** 不推断后端版本；变化即开始新会话。 */
	readonly version: string;
}
export interface FormRequest extends FormIdentity {
	readonly page: FormPage;
	readonly signal: AbortSignal;
}
export interface FormWrite extends FormRequest {
	readonly operationId: string;
}
export interface FormReceipt {
	readonly operationId: string;
	readonly entity: string;
	readonly version: string;
	readonly summary: string;
}
export type FormLoad =
	{ readonly status: 'found'; readonly model: AsamFieldModel } | { readonly status: 'empty' };
export type FormSubmit =
	| { readonly status: 'success'; readonly receipt: FormReceipt }
	| {
			readonly status: 'failure';
			readonly message: string;
			readonly issues?: readonly AsamEditIssue[];
	  }
	| { readonly status: 'unknown'; readonly message: string };
export type FormVerify =
	| { readonly status: 'success'; readonly receipt: FormReceipt }
	| { readonly status: 'not-applied' | 'unknown' };
export interface FormServices {
	load(request: FormRequest): Promise<FormLoad>;
	validate(
		dto: Readonly<AsamFieldModel>,
		request: FormRequest
	): Promise<readonly AsamEditIssue[]>;
	submit(dto: Readonly<AsamFieldModel>, request: FormWrite): Promise<FormSubmit>;
	verify(request: FormWrite): Promise<FormVerify>;
	/** P07 的真实异步依赖读取；不向库注入业务 URL。 */
	departments(
		region: string,
		request: FormRequest
	): Promise<readonly { value: string; label: string }[]>;
}
export interface VersionedDraft {
	readonly format: 'asam-forms-draft-v1';
	readonly identity: FormIdentity;
	readonly page: FormPage;
	readonly model: AsamFieldModel;
}
export interface DraftAdapter {
	read(request: FormRequest): Promise<VersionedDraft | undefined>;
	write(draft: VersionedDraft, request: FormRequest): Promise<void>;
}
export interface FormPageProps {
	readonly identity: FormIdentity;
	readonly services: FormServices;
	readonly disabled?: boolean;
	readonly readonly?: boolean;
	readonly size?: AsamControlSize;
	readonly configurationVersion?: string;
	/** 宿主借入会话由宿主销毁；其 page/services/identity 必须匹配。 */
	readonly session?: FormPageSession;
	readonly draftAdapter?: DraftAdapter;
}
export interface FormPageEvents {
	saved: [receipt: FormReceipt];
	cancel: [];
}
export interface FormPageExpose {
	reload(): Promise<void>;
	submit(): Promise<boolean>;
	verify(): Promise<void>;
	cancel(): void;
}
export interface FormSessionConfig {
	readonly page: FormPage;
	readonly services: FormServices;
	readonly identity: FormIdentity;
	readonly bindings: readonly AsamFieldViewBinding[];
	readonly coordinator?: AsamWriteCoordinator;
	/** 与借入协调器一起跨服务配置替换保留原operationId。 */
	readonly pendingOperations?: Map<string, string>;
	readonly canWrite?: () => boolean;
	readonly validate?: (
		model: Readonly<AsamFieldModel>,
		signal: AbortSignal
	) => Promise<readonly AsamEditIssue[]>;
	readonly onSaved?: (receipt: FormReceipt) => void;
}
export type FormPageSession = ReturnType<typeof createFormPageSession>;

export interface AdvancedRow {
	rowKey: string | number;
	name: string;
	quantity: number;
}
export interface AdvancedModel {
	profile: { name: string; code: string; enabled: boolean; region: string; department: string };
	finance: {
		amount: number;
		currency: string;
		costCode: string;
		invoice: boolean;
		taxNote: string;
	};
	contact: {
		name: string;
		phone: string;
		email: string;
		showPrivate: boolean;
		privateNote: string;
	};
	policy: {
		publish: boolean;
		keepNote: string;
		clearNote: string;
		date: string;
		resourceId: string | null;
	};
	items: AdvancedRow[];
}
