Reference ​

API and behavior

Use Types.ts as the source of truth for types. Copy the Vue files, recipes, and documentation from the same release.

Edit, Query, GrantNode, and the sample DTOs enforce complete field allowlists at runtime. A missing field, extra field, invalid type, accessor, duplicate ID, or sparse ID array rejects the entire input. The version has no zero default. Set parentId explicitly to null or a valid typed ID. Use queryProjectionCodec for list queries. It restores only the empty query values that the list controller deliberately omits, then validates the full Query. Project Row to Edit in the host so that the row ID and private backend fields stay out of the edit payload.

A receipt verified by another instance advances the confirmed baseline and preserves the local dirty draft. The operation snapshot can update the selection only when this instance issued the original operation and no later edits exist. The example implements logout. Bootstrap waits for the router's first navigation before setting up the bridge so that deep links work.

Contract Input, output, and responsibility
AdministrationHost Supplies borrowed security, runtime, writes, operations, receipts, services, size, confirm, and unknownRoles.
AdministrationServices Supplies version, three AsamCrudServices groups, roleOptions, menuNodes, and grants. The host chooses the service endpoints.
Query keyword, status, role, and context. Set role to a typed ID or null.
UserEdit / UserRow name, account, status, roleIds, context, note, and version. The row adds id.
RoleEdit / RoleRow name, code, enabled, members, note, context, and version. The host defines the semantics of the read-only row members value.
MenuEdit / MenuRow parentId, title, kind, permissionCode, enabled, grantable, and version. The row adds id.
GrantNode A typed id and parentId, plus title, kind, permissionCode, enabled, grantable, and version.
GrantSnapshot Complete read-only input with subject, scope, version, nodes, direct, and unavailable.
GrantOperation Immutable record with operationId, subject, scope, serviceVersion, version, and direct.
GrantService load(subject, Request), save(operation, Request), and verify(operation, Request).
Request signal, isCurrent, and scope. Reauthorize writes on the host backend before applying side effects.
GrantResult Success with a version, confirmed failure with a reason of conflict, validation, or denied, or unknown.
GrantReceipt The original operation, status of sending, success, failure, or unknown, and the result. The host retains the map across unmounts.
GrantEditor expose open(typedId) and editor. Emits closed on close and clears only its local state on unmount.
createGrantEditor Refs snapshot, selected, filter, status, message, dirty, tree, visible, and writable. Methods open, toggle, selectVisible, save, verify, close, reload, invalidate, and dispose.
AdministrationApp Props host, family (minimal, brand, or technology), and mode (light or dark). Provides controls and recovery slots and exposes navigation.

Use the CRUD controller's public contract for CRUD operations. Read current details from the service and discard stale rows as edit targets. Use explicit codecs to project service DTOs into fields safe to display. Carry the version in the hidden edit payload and let the host map it to its backend version or ETag. The example uses string statuses. Use an explicit codec when the backend uses booleans, enums, or numbers.

GrantEditor moves from closed to loading, then to ready or error. From ready, a save moves through saving and returns to ready or unknown. Verification moves from unknown through verifying and returns to ready or unknown.

Invalidation closes the editor immediately. A failed read leaves the tree empty. Confirm before refreshing a dirty draft. A save confirms the submitted snapshot and preserves later edits. Correct a confirmed failure before resubmitting. For an unknown result, verify the original operation.

Migration (Chinese)

这是新增模板，没有删除既有包接口。复制模板目录及 导航模板/会话与权限模板 的相对依赖；保留正常包 import。 从旧管理页迁入时逐项替换：

  1. 将 Row/Edit/Query 映射到 Types.ts；使用明确 codec 保留原 typed ID、版本与原始服务映射。
  2. 注入三组 AsamCrudServices 和应用持有的 writes/operations，不把各页未决写放到临时组件内。
  3. 接入宿主 SecurityAdapter 与 scopeKey。给每个 route 明确读取规则，写前单独检查权限；禁用通配超级角色推导。
  4. 将后端授权模型转换为 direct 集合，明确全量/差额、不可授保留/拒绝、版本与 unknown 核实策略。
  5. 服务替换更改 version 和服务引用；失效优先清数据。普通离开可以询问丢弃，安全失效不能让确认保留旧主体。
  6. 删除旧“失败自动重试写”的流程；对 unknown 使用原 operationId 核实。

Directory/Catalog 的真实可运行合成映射见 Codecs.ts 与 Fixture.ts。 真实后端授权引擎、认证服务器、租户平台及真实 CL 页面不属于本模板，接入方保留这些职责。

Edit/Query/GrantNode 与示例 DTO 的字段必须完整且无额外字段；service.load 显式返回 Edit，不把含 id 的 Row 直接传给 Edit codec。新增字段同时更新 Types、字段定义、codec 白名单和 DTO adapter。列表控制器 空查询省略只经 queryProjectionCodec 适配，不把缺失 Edit/parentId/version 默认为合法值。保留目标工程的依赖检查配置与有效锁。

Usage

The administration template is an editable Vue 3 application for users, roles, and menus. Its entry point is AdministrationApp.vue. It includes UsersPage.vue, RolesPage.vue, MenusPage.vue, and the GrantEditor.vue grant editor. It uses the standard @asam-ui/ui and @asam-ui/pro packages. The host supplies authentication and backend authorization.

Copy the template directory and same-release app/security and app/navigation dependencies, preserving their relative paths. Install compatible versions of UI, Pro, Vue, Element Plus, and Vue Router. Start from examples/main.ts and load the Element Plus, UI, and Pro styles in that order. The example App.vue provides a local synthetic host. Replace its adapters when you integrate the template.

Application and design variants ​

Use the minimal.html, brand.html, and technology.html production entry points or select the corresponding family with ?family=minimal, ?family=brand, or ?family=technology. All three application shells share /users, /roles, and /menus. The public recovery route is /safe. They support the host's light and dark themes, a 390 px viewport, keyboard focus, and control sizes of 40, 36, 32, and 28 px. Buttons use color and movement for feedback. Reduced motion disables movement, and operations are available immediately.

Layout and theme ​

The minimal layout uses a horizontal shell and subtle dividers. The brand layout uses a sidebar to emphasize identity and content hierarchy. The technology layout uses a narrow rail and strong tone contrast. All three styles share the same data, operations, and permission contract. Follow the project's Vue, ASAM, token, accessibility, and immediate interaction requirements when styling the template.

Host responsibilities ​

Types.ts defines the contract. The host owns security, runtime, writes, operations, receipts, services, and size. Pages release the watchers, read requests, subscriptions, and controllers they create. AdministrationApp releases its own navigation bridge and guard. Disposal of borrowed security, router, runtime, and write coordination belongs to their owner. The example app creates and disposes these resources. Each instance uses its own router and runtime and can share security and host receipts.

Use security.check and permission from the security adapter. Set a separate read rule for each protected route. Hiding menu items controls visibility. Before a write, synchronously check read, write, and readOnly. Pending access, errors, and invalidation close restricted pages. Invalidation immediately clears drafts and trees. Switch the runtime scope before mounting a new page. Confirm service replacement in the host. Both service identity and version identify the page generation and prevent an earlier read from overwriting a new page, even if the service ignores cancellation.

The example uses synthetic local data: 100 users, 30 roles, 50 nodes, 20 rows per page, four query inputs, six edit fields, and reads delayed by 100 ms. The host supplies real accounts, endpoints, and access rules. Return display-safe messages and field errors from adapters so that sensitive errors and credentials stay out of the UI.

Writes and recovery ​

CRUD uses useAsamCrudController, AsamCrudPage, and AsamCrudServices from CRUD pages. Freeze the version with the edit payload or delete target. Report failure only when the service confirms it did not apply the write. Otherwise record an unknown result and retain its original operationId for verification. Keep a result per delete target. If a write succeeds and the list refresh fails, retry the refresh.

The grant editor works with direct grants. The tree uses check-strictly and excludes structural parents and disabled nodes from new grants. Filtering preserves hidden selections. Use the unavailable preserve or reject policy returned by the load service for old grants that are unknown or can no longer be assigned. Preserve entries appear in the summary and survive clearing visible selections. A pending receipt for the same scope and subject prevents a new operation ID from resending the write.

Users can edit the tree while a save is in progress. Success confirms the submitted snapshot while later edits remain dirty. Check the current generation before confirmation, before the service call, and after the asynchronous result. The host retains host.receipts when leaving the scope and can verify the original operation using its serviceVersion.

Validate an entire menu tree for duplicate nodes, orphans, cycles, and invalid typed IDs before showing it. The UI uses typed JSON tuples as keys and returns the original typed ID. Number 0, string '0', and root null have distinct meanings. Tree behavior comes from AsamTree.

Host adapter examples ​

Codecs.ts defines DirectoryUserDTO and CatalogUserDTO with different field shapes. examples/Fixture.ts uses both mappings for reads and writes. The Directory adapter saves the whole grant set. The Catalog adapter computes set differences. Both use the same set contract in the UI.

Implement AdministrationServices and handle DTOs, versions, service authorization, and reference constraints in the host. The host chooses endpoint URLs and authorization rules. roleOptions supplies candidates, and the host's unknownRoles policy determines whether to preserve or reject unknown user roles. A missing candidate never grants new access.

See the AI development recipe, API reference, and migration guide for integration and verification.

Types.ts · Type source
ts
import type { InjectionKey, Ref } from 'vue';
import type { AsamControlSize, AsamDataRuntime } from '@asam-ui/ui';
import type {
	AsamCrudServices,
	AsamWriteCoordinator,
	AsamTableOperationCoordinator
} from '@asam-ui/pro';
import type { createSecurity } from '@asam-ui/pro/application/security';
type SecurityController = ReturnType<typeof createSecurity>;

export type Id = string | number;
export type Entity = 'users' | 'roles' | 'menus';
export interface Query {
	keyword: string;
	status: string;
	role: Id | null;
	context: string;
}
export interface UserEdit {
	name: string;
	account: string;
	status: string;
	roleIds: Id[];
	context: string;
	note: string;
	version: number;
}
export interface UserRow extends UserEdit {
	id: Id;
}
export interface RoleEdit {
	name: string;
	code: string;
	enabled: string;
	members: string;
	note: string;
	context: string;
	version: number;
}
export interface RoleRow extends RoleEdit {
	id: Id;
}
export interface MenuEdit {
	parentId: Id | null;
	title: string;
	kind: string;
	permissionCode: string;
	enabled: string;
	grantable: string;
	version: number;
}
export interface MenuRow extends MenuEdit {
	id: Id;
}
export interface RoleOption {
	id: Id;
	name: string;
	enabled: boolean;
}
export interface GrantNode {
	id: Id;
	parentId: Id | null;
	title: string;
	kind: string;
	permissionCode: string;
	enabled: boolean;
	grantable: boolean;
	version: number;
}
export interface GrantSnapshot {
	subject: Id;
	scope: string;
	version: string;
	nodes: readonly GrantNode[];
	direct: readonly Id[];
	unavailable: 'preserve' | 'reject';
}
export interface Request {
	signal: AbortSignal;
	isCurrent(): boolean;
	scope: string;
}
export interface GrantOperation {
	readonly operationId: string;
	readonly subject: Id;
	readonly scope: string;
	readonly serviceVersion: string;
	readonly version: string;
	readonly direct: readonly Id[];
}
export type GrantResult =
	| { status: 'success'; version: string }
	| { status: 'failure'; reason: 'conflict' | 'validation' | 'denied' }
	| { status: 'unknown' };
export interface GrantReceipt {
	readonly operation: GrantOperation;
	status: 'confirming' | 'sending' | 'success' | 'failure' | 'unknown';
	result?: GrantResult;
}
export interface GrantService {
	load(subject: Id, request: Request): Promise<GrantSnapshot>;
	save(operation: GrantOperation, request: Request): Promise<GrantResult>;
	verify(operation: GrantOperation, request: Request): Promise<GrantResult>;
}
export interface EntityServices<Row extends object, Edit extends object> {
	crud: AsamCrudServices<Row, Query, Edit, Id>;
}
export interface AdministrationServices {
	version: string;
	users: EntityServices<UserRow, UserEdit>;
	roles: EntityServices<RoleRow, RoleEdit>;
	menus: EntityServices<MenuRow, MenuEdit>;
	roleOptions(request: Request): Promise<readonly RoleOption[]>;
	menuNodes(request: Request): Promise<readonly GrantNode[]>;
	grants: GrantService;
}
export interface AdministrationHost {
	security: Pick<SecurityController, 'state' | 'check' | 'permission' | 'onInvalidate'>;
	runtime: AsamDataRuntime;
	writes: AsamWriteCoordinator;
	operations: AsamTableOperationCoordinator;
	/** Host owned, retained across page removal and security invalidation. */
	receipts: Map<string, GrantReceipt>;
	services: Ref<AdministrationServices>;
	size: Ref<AsamControlSize>;
	confirm(message: string): Promise<boolean>;
	unknownRoles: 'preserve' | 'reject';
	leaves?: Set<() => Promise<boolean>>;
}
export const administrationKey: InjectionKey<AdministrationHost> = Symbol('asam-administration');
