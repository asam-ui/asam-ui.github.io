Frontend permission display ​

Example data, control text, messages and source comments may be in Chinese. Viewer controls and API headings use English. Untranslated API descriptions are marked.

AsamPermission shows or disables a section according to an application-provided permission policy.

When to use it ​

Pass a permission string and configure a synchronous check in the nearest AsamApplicationProvider (Chinese). The check can return a boolean or one of allowed, denied, pending, and error. A missing check yields pending. An invalid permission or a check that throws or returns an invalid value, including a promise, yields error. Load asynchronous permissions in the application and have the check read the current reactive state.

The default and fallback slots receive status, visible, and disabled. The component instance also exposes the computed state. The provider chooses the default mode, which resolves to hide unless configured otherwise. Set mode to override that choice for a region.

Showing or hiding content ​

In hide mode, the default slot renders only for allowed. Use the fallback slot to explain a denied, pending, or error state. The example allows viewing the project and shows fallback text for the delete permission.

Example: hide

<template>
	<div class="pro-example-stack">
		<AsamApplicationProvider :config="config">
			<div class="pro-example-stack">
				<AsamPermission permission="project:view"><p>可以查看项目。</p></AsamPermission>
				<AsamPermission permission="project:delete">
					<AsamButton type="primary">删除项目</AsamButton>
					<template #fallback><p>暂无删除权限。</p></template>
				</AsamPermission>
			</div>
		</AsamApplicationProvider>
	</div>
</template>

<script setup lang="ts">
import { AsamButton } from '@asam-ui/ui';
import { AsamApplicationProvider, AsamPermission } from '@asam-ui/pro/components';
const config = { permission: { check: (permission: string) => permission === 'project:view' } };
</script>

Disabling an action ​

In disable mode, the content stays visible. The component makes the region inert for any state other than allowed. Bind the slot's disabled value to the action control as well so it reflects the permission state visually. Keep guarded controls inside the region. Content teleported elsewhere and programmatic calls bypass the UI guard.

Example: disable
