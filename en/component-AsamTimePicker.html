Time picker ​

Example data, control text, messages and source comments may be in Chinese. Viewer controls and API headings use English. Untranslated API descriptions are marked.

Interactive examples, TypeScript and JavaScript source, and the generated API reference are included on this page.

When to use it ​

Edit time through an input and popup. Without valueFormat, the native Date model is preserved. Set valueFormat explicitly for strings or timestamps. format controls display; valueFormat controls model text or timestamps.

Native default models ​

The native control resolves omitted behavioral defaults. The complete SFC compares explicit undefined, null and empty strings. Output preserves the original model type; cleared values are not normalized to null. Invalid-input diagnostics and compatibility limitations follow the pinned native version.

ASAM extensions and migration ​

disabledHours, disabledMinutes and disabledSeconds can change dynamically. Range callbacks receive the start/end role and comparison endpoint. arrowControl uses up/down arrows. Clear, change, update:modelValue and keydown forward native events with all arguments and their order, without extra events or deduplication. Date disabling with disabledDate belongs to DatePicker/Panel; time spinners do not add date selection.

Four-size inheritance follows forms and ConfigProvider. Empty models allow null. Display format does not change storage; configure date-token case using valueFormat rules. validateEvent controls form validation triggers and teleported controls popup placement. For one date/time use DatePicker with type=datetime; use DateTimeRangePicker for two independent date/time endpoints.

Reading the API ​

The pinned documentation's deprecated label conflicts with the actual source: native props declare ariaLabel, not label. Migrate to aria-label (ariaLabel in TS objects); it reaches the real input. The basic example demonstrates this. ASAM does not add a label interface with no native implementation.

props, Events, Slots and Exposes use current public types and runtime defaults. Combined props apply by branch; unknown or undeclared defaults do not mean false or empty. Complete standalone Demo.vue files inline their local helpers, data and assets.

<script lang="ts" setup>
import type { AsamTimeValue } from '@asam-ui/ui';
import { AsamTimePicker } from '@asam-ui/ui';
defineOptions({ name: 'AsamTimePickerofficialtimepickerbasicrangeExample' });

import { ref } from 'vue';

const value1 = ref<AsamTimeValue>(new Date(2016, 9, 10, 18, 30));

const makeRange = (start: number, end: number) => {
	const result: number[] = [];
	for (let i = start; i <= end; i++) {
		result.push(i);
	}
	return result;
};
const disabledHours = () => {
	return makeRange(0, 16).concat(makeRange(19, 23));
};
const disabledMinutes = (hour: number) => {
	if (hour === 17) {
		return makeRange(0, 29);
	}
	if (hour === 18) {
		return makeRange(31, 59);
	}
	return [];
};

Some clear-sentinel/format combinations in 2.14.7 produce empty displays, formatting exceptions or diagnostics. These are native compatibility limitations. Callers needing nullable business models should adapt them in their own advanced data layer. DateTimeRangePicker/DateTimePicker preserve their explicit complete-range/null composition protocol. To reproduce the former default string model, supply valueFormat explicitly: YYYY-MM-DD for dates, HH:mm:ss for times.
