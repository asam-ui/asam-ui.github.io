Pro project integration and version checks ​

Back to Development Expert

When using an agent to compose Pro components, confirm that the installed packages and documentation are paired before selecting a recipe for fields, lists, editing, details, or templates. The base component documentation MCP and the local Pro expert resources serve different purposes. Check actual capability availability even when their version strings match.

Discover capabilities from a requirement ​

In the paired local expert tools, use agent_discover to search by intent, symbol, or tag. Pass an ID returned by that search to agent_read. Request the API, example, recipe, migration, or source sections you need, and use pagination to read complete results.

json
{ "query": "AsamCrudPage" }

Use IDs from the discovery results. When documentation mentions a symbol, verify that the installed package supplies the public runtime export, types, styles, and required peer dependencies.

Integrate with an existing project ​

Follow the project's existing import conventions and preserve its configuration, business code, and data providers. Import components through the installed packages' public entry points. Load the Element Plus, UI, and Pro styles as documented by their packages and resolve the packages through their normal entry points.

Define the field model, null handling, conversion, and validation rules before composing search, list, editing, and detail controllers. Handle 0, false, empty strings, null, and omitted values according to their distinct business meanings. The application supplies requests, tenant context, permissions, and business services.

Use the Pro component catalog to find working composition examples and complete source. Replace the local example data with your business APIs.

Choose a recipe ​

Pro resources groups fields, forms, tables, application capabilities, and page templates by scenario. Use recipes for incremental changes. For specific props, events, slots, and instance methods, consult the component page and the declarations in the installed package.

Some named migration methods may be available only on the website. If the tools cannot find a method, follow the website instructions and adapt the project manually against the installed package. Record how the migration was carried out.

Read reference screenshots and operate interactive demos before implementation. Identify visible layout and any behavior the reference leaves unspecified. Describe normal, empty, error, and loading states, save the implementation as ordinary Vue source, and verify how it runs.

Verify and modify ​

Use agent_inspect and agent_diagnose to inspect explicitly selected projects and files. Use agent_validation_plan to read the validation plan. Documentation lookups and read-only plans leave project commands and product code changes to the authorized host.

The authorized host runs type checks, builds, source review, and applicable runtime checks. Before repairing a problem, identify the files that may be changed, existing user changes, and the assertions that must be preserved. Verify actual behavior after editing and report any remaining checks as unverified.

Migration limits ​

After looking up migration guidance, check the supported input format and target version. A named recipe applies to its specified legacy model. For unknown versions, unknown formats, or unsupported automatic rewrites, stop the automated change and follow the documented manual adaptation process.

Verify documentation, component, and host tool updates independently. The project continues to use its installed component packages until they are updated separately.

See Development Expert for local host installation and removal.
