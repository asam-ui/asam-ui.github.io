Installation and integration ​

Install ASAM UI in a Vue 3, TypeScript, and Vite project, then choose full registration, manual on-demand imports, or automatic on-demand imports, the recommended option. See Styles, themes, and providers to configure themes or data.

Mode Using components When to choose it Template types
Full registration Call app.use(AsamUIFull) and use components directly in templates Quick setup where loading all component JavaScript is acceptable @asam-ui/ui/global
Manual on-demand Import components in each SFC Control each import explicitly Follow component imports
Automatic on-demand A resolver adds imports based on template usage Multipage Vue and Vite projects The plugin generates components.d.ts

1. Install dependencies ​

Install @asam-ui/ui in your Vue project. In an existing project, add only the dependencies you are missing. This version supports Vue >=3.5.34 <3.6.0 and Element Plus 2.14.7. For a new Vue and Vite project, use the following versions:

sh
pnpm add @asam-ui/ui@2.0.1 vue@3.5.34 element-plus@2.14.7
pnpm add -D vite@8.0.10 @vitejs/plugin-vue@6.0.9 typescript@6.0.3 vue-tsc@3.3.11

Optional standalone icons ​

Install the published icon package if you need icons. The core stylesheet and the full registration plugin do not register icons.

sh
pnpm add @asam-ui/icons-vue@1.0.1

@asam-ui/icons-vue uses the same Vue peer range, has no Element Plus dependency, and ships no CSS. Choose a named import from the root or a default import from a case-sensitive icon subpath.

ts
import { Search } from '@asam-ui/icons-vue';
// Alternatively: import Search from '@asam-ui/icons-vue/Search';

Pass the imported icon to an ASAM component, for example <AsamButton :icon="Search">Search</AsamButton>. The icon package has no default root export. When migrating icon imports, check the actual ASAM icon names. The component resolver does not import icons.

2. Shared Vue and Vite setup ​

For manual imports and full registration, use this vite.config.ts:

ts
import { defineConfig } from 'vite';
import vue from '@vitejs/plugin-vue';

export default defineConfig({ plugins: [vue()] });

In index.html, include <div id="app"></div> and <script type="module" src="/src/main.ts"></script>. Merge the following baseline into the application's own TypeScript configuration. Preserve existing paths, types, includes, and project references.

json
{
	"compilerOptions": {
		"target": "ES2022",
		"module": "ESNext",
		"moduleResolution": "Bundler",
		"strict": true,
		"skipLibCheck": true,
		"noEmit": true,
		"lib": ["ESNext", "DOM"],
		"types": ["vite/client"]
	},
	"include": ["src/**/*.ts", "src/**/*.vue", "components.d.ts", "vite.config.ts"]
}

3. Full registration ​

Apply the Element Plus stylesheet before the ASAM UI stylesheet for full registration and manual imports.

Install AsamUIFull in src/main.ts to register components globally and configure themes and data:

ts
import { createApp } from 'vue';
import AsamUIFull from '@asam-ui/ui/full';
import 'element-plus/dist/index.css';
import '@asam-ui/ui/style.css';
import App from './App.vue';

createApp(App).use(AsamUIFull).mount('#app');

Append "@asam-ui/ui/global" to compilerOptions.types, for example ["vite/client", "@asam-ui/ui/global"]. This optional template type entry has no runtime effect. Configure it in TypeScript instead of importing it from main.ts.

src/App.vue can use globally registered components directly:

vue
<template>
	<AsamButton @click="count++">Clicks: {{ count }}</AsamButton>
</template>

<script setup lang="ts">
import { ref } from 'vue';
const count = ref(0);
</script>

AsamUIFull is also a named export. It accepts the AsamUIOptions fields theme, target, dataProvider, and dataScope. The default and named root AsamUI exports remain available and initialize the theme and runtime without global registration. Install one plugin per app and pass options on the first call. Full registration retains unused registered component JavaScript. Choose manual or automatic imports when you want to omit unused components.

4. Manual on-demand imports ​

Load both stylesheets explicitly in src/main.ts. Install the root plugin when the app needs runtime configuration.

ts
import { createApp } from 'vue';
import { AsamUI } from '@asam-ui/ui';
import 'element-plus/dist/index.css';
import '@asam-ui/ui/style.css';
import App from './App.vue';

createApp(App).use(AsamUI).mount('#app');

Import the components and types you use in src/App.vue:

vue
<template>
	<AsamButton @click="count++">Clicks: {{ count }}</AsamButton>
	<AsamInput ref="input" v-model="name" placeholder="Enter a name" />
</template>

<script setup lang="ts">
import { ref } from 'vue';
import { AsamButton, AsamInput } from '@asam-ui/ui';
import type { AsamInputExpose } from '@asam-ui/ui';

const count = ref(0);
const name = ref('');
const input = ref<AsamInputExpose>();
</script>

Static components using default styles can work without installing AsamUI. Configure custom themes, URL requests, and dictionaries as described in Styles, themes, and providers. Manual imports require neither unplugin-vue-components nor global component types. The package uses ESM, so a bundler can omit unused component JavaScript. The CSS entry still contains the full stylesheet.

5. Automatic on-demand imports (recommended) ​

Install the template component plugin in the consuming project:

sh
pnpm add -D unplugin-vue-components@32.1.0

In vite.config.ts, add the resolver to the existing Components configuration, preserving any other resolvers.

ts
import { defineConfig } from 'vite';
import vue from '@vitejs/plugin-vue';
import Components from 'unplugin-vue-components/vite';
import { AsamUIResolver } from '@asam-ui/ui/resolver';

export default defineConfig({
	plugins: [
		vue(),
		Components({
			dirs: [],
			resolvers: [AsamUIResolver()],
			dts: 'components.d.ts'
		})
	]
});

dirs: [] limits this example to resolver-based imports. Preserve the consuming project's dirs if it scans local components. Scanning the ASAM package source is unnecessary. In src/main.ts:

ts
import { createApp } from 'vue';
import { AsamUI } from '@asam-ui/ui';
import App from './App.vue';

createApp(App).use(AsamUI).mount('#app');

In src/App.vue:

vue
<template>
	<AsamButton @click="count++">Clicks: {{ count }}</AsamButton>
	<asam-input v-model="name" placeholder="Enter a name" />
</template>

<script setup lang="ts">
import { ref } from 'vue';
const count = ref(0);
const name = ref('');
</script>

AsamUIResolver() supports PascalCase and kebab-case template component names. Import functions, types, provider and theme APIs, and components used directly from JavaScript or TypeScript explicitly.

Run pnpm exec vite build or compile a page that uses the components with the development server to generate components.d.ts. Run pnpm exec vue-tsc --noEmit afterward. Include the generated declaration file in the application's TypeScript config.

The resolver injects the styles for matching template components. If you import components only in scripts or have no matching template components, follow the manual stylesheet instructions. Load app overrides after the component styles.

On-demand directive imports ​

Use the separate AsamUIDirectiveResolver() with directives: true for automatic directive imports:

ts
import { AsamUIResolver, AsamUIDirectiveResolver } from '@asam-ui/ui/resolver';

Components({
	dirs: [],
	directives: true,
	resolvers: [AsamUIResolver(), AsamUIDirectiveResolver()],
	dts: 'components.d.ts'
});

v-asam-loading resolves to the public vAsamLoading export. The resolver also supports v-asam-infinite-scroll, v-asam-popover, v-asam-click-outside, v-asam-mousewheel, v-asam-trap-focus, and v-asam-repeat-click. For manual imports, use the actual root export name and Vue's local naming convention or register it with app.directive. Component auto-import does not enable directive resolution by itself.

6. Styles, themes, and providers ​

The complete stylesheet loads Element Plus base styles before ASAM UI styles. Load app overrides last. The stylesheet covers all components and you can still import JavaScript components on demand.

Stylesheet compatibility ​

For the existing stable npm release, import the styles in this order. If your app already loads Element Plus styles, add the second import after them.

ts
import 'element-plus/dist/index.css';
import '@asam-ui/ui/style.css';

The package still uses the Element Plus runtime. Configure imports for any El* components used directly by your app.

The following src/provider.ts is a runnable local example with no backend requests:

ts
import type { AsamDataProvider } from '@asam-ui/ui';

export const dataProvider: AsamDataProvider = {
	async request() {
		return [{ label: 'Ready', value: 'ready' }];
	},
	dict: {
		async get() {
			return [{ label: 'Ready', value: 'ready' }];
		}
	}
};

Import the provider in main.ts and pass options when installing the selected plugin:

ts
import { dataProvider } from './provider';

// Use AsamUIFull for full registration and AsamUI for on-demand imports.
app.use(AsamUI, {
	dataProvider,
	dataScope: 'demo-session',
	theme: { color: { primary: '#345678' } }
});

Create app with const app = createApp(App). Call use before app.mount('#app'). URL and dictionary sources require injection. Static arrays and API functions can run without a provider. The host owns HTTP, authentication, abort-signal forwarding, response adaptation, and error notices. To install only the provider, use provideAsamData(app, provider, { scope }). Update context with setAsamDataScope when the user or tenant changes.

For a Yudao host, use the matching adapter from npm, pnpm add @asam-ui/ui-yudao@2.0.1. Import createYudaoProvider from @asam-ui/ui-yudao to use the existing request client and dictionary store.

7. Verify and migrate ​

Build and type-check the application, for example with pnpm exec vite build and pnpm exec vue-tsc --noEmit. Start the application and check component styles, button clicks, and input. If the app has a provider, check requests and dictionaries too.

  • When moving from the root AsamUI plugin to full registration, replace the plugin import and installation and append the global component types. Preserve theme and provider options.
  • When switching from full registration to on-demand imports, remove the full plugin and global types. Add component imports in manual mode or generate declarations in automatic mode. Keep the root AsamUI initialization where needed.
  • In CommonJS configuration, load the resolver with await import('@asam-ui/ui/resolver') and add it to the existing Vite plugin configuration.
