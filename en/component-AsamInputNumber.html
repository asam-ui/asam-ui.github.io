Number input ​

Example data, control text, messages and source comments may be in Chinese. Viewer controls and API headings use English. Untranslated API descriptions are marked.

Interactive examples, TypeScript and JavaScript source, and the generated API reference are included on this page.

When to use it ​

Enter quantities and numbers with limited precision. v-model is number, null or undefined; change supplies both the new and previous values. For formatted text, see Input.

Bounds and steps ​

min / max set bounds, step sets the increment and stepStrictly restricts values to multiples of the step. Omitted bounds retain the pinned native defaults, Number.MIN_SAFE_INTEGER / Number.MAX_SAFE_INTEGER. Committing an unsafe integer clamps it to those bounds. Configure explicit bounds when the application requires another range.

precision controls decimal places. The step must not have more decimal places than the precision. valueOnClear specifies the cleared value; disabledScientific prevents scientific-notation characters.

Sizes and inheritance ​

large, big, default and small are the four densities. An explicit size overrides inheritance. When omitted, resolution follows component, group, form, ConfigProvider and finally default. Switch the provider in the example to observe updates.

ASAM extensions and migration ​

Four-size inheritance is preserved. Use a numeric model; clearing follows valueOnClear. Do not migrate a string model directly. Default clearing and invalid input can produce null. input, update:modelValue and both new/old values in change preserve that empty value.

Formatting and parsing ​

formatter changes display and parser parses edited text. Models and events remain number | null | undefined. Dynamic formatter changes are passed to the native input. ASAM does not rebuild the input with a key or repair native selection limitations when switching text/number types. tabindex applies to the actual input.

Empty values, invalid input and recovery ​

Without valueOnClear, clearing returns null. Explicit values may be a number, null, min or max. Invalid edits can produce null; entering a valid number recovers. The model, update:modelValue, input, and the new/old change values all allow number | null | undefined. Do not treat null as a string or remove it from the event contract.

Example: null-values

Show source
Example source ZIPComplete project ZIP
vue
<template>
	<div class="example">
		<AsamInputNumber
			v-model="value"
			aria-label="默认清空数字"
			@input="record('input', [$event])"
			@update:model-value="record('update', [$event])"
			@change="recordChange"
		/>
		<AsamButton type="default" native-type="button" @click="value = 1">恢复为 1</AsamButton>
		<AsamInputNumber
			v-model="amount"
			:formatter="formatter"
			:parser="parser"
			aria-label="非法格式金额"
			@change="recordAmountChange"
		/>
		<AsamButton type="default" native-type="button">提交格式金额</AsamButton>
		<output>{{ JSON.stringify({ value, amount, events }) }}</output>
		<p class="example-paragraph">
			清空默认产生 null；输入非法格式也可产生 null。重新输入数字会从空值恢复，change
			保留新旧值。
		</p>
	</div>
</template>

<script lang="ts" setup>
import { ref } from 'vue';
import { AsamButton, AsamInputNumber } from '@asam-ui/ui';
import type { AsamInputNumberEmits } from '@asam-ui/ui';
defineOptions({ name: 'AsamInputNumberNullValuesExample' });
const value = ref<number | null | undefined>(1);
const amount = ref<number | null | undefined>(2);
const events = ref<{ name: string; args: (number | null | undefined)[] }[]>([]);
function record(name: string, args: (number | null | undefined)[]) {
	events.value.push({ name, args });
}
function recordChange(...args: AsamInputNumberEmits['change']) {
	record('change', args);
}
function recordAmountChange(...args: AsamInputNumberEmits['change']) {
	record('amount-change', args);
}
const formatter = (value: string) => (value === '' ? '' : '$' + value);
const parser = (value: string) => value.replace(/[$,]/g, '');
</script>

Reading the API ​

The reference uses public types and runtime defaults. An unknown or undeclared default does not mean false, empty or unsupported. Omitted size inherits context; omitted disabled inherits form disabling. validateEvent controls validation events and should not be replaced by disabling the control.

Dynamic form state and accessibility bounds ​

Updates to disabled and min / max are delegated to the underlying input. Native 2.14.7 initializes some ARIA attributes at mount, so subsequent changes may leave stale aria-disabled, aria-valuemin or aria-valuemax. ASAM preserves this compatibility limitation; it does not rewrite attributes with MutationObserver or remount to restore selection.
