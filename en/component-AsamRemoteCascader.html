Remote Cascader ​

Example data, control text, messages and source comments may be in Chinese. Viewer controls and API headings use English. Untranslated API descriptions are marked.

Load asynchronous options in a cascader with reload and cancellation.

Basic usage ​

The example loads options through a local Promise-based function and demonstrates model updates, pausing, and reloading. Requests run entirely within the demo.

<script lang="ts" setup>
import { ref } from 'vue';
import { AsamCheckboxItem, AsamButton, AsamRemoteCascader, defineAsamOptions } from '@asam-ui/ui';
import type { AsamRemoteCascaderExpose, AsamApiRequest } from '@asam-ui/ui';

defineOptions({ name: 'AsamRemoteCascaderBasicDemoExample' });
interface Item {
	label: string;
	value: string;
	children?: readonly Item[];
}
interface Query {
	text: string;
}
const value = ref<string | null>(null);
const active = ref(true);
const control = ref<AsamRemoteCascaderExpose<string, Item>>();
const error = ref('');
const result = ref('');
const items: readonly Item[] = [
	{ label: '准备', value: 'ready', children: [{ label: '就绪', value: 'available' }] },
	{ label: '进行', value: 'running' }
];
const api: AsamApiRequest<Query, readonly Item[]> = async (params, context) => {
	context.signal.throwIfAborted();
	return items.filter((item) => item.label.includes(params.text));
};
const factory = defineAsamOptions<string, Item>();
const dataSource = factory.api({
	api,
	params: { text: '' },
	transform: (response) => response,
	fieldNames: { label: 'label', value: 'value', children: 'children' }
});
async function reload() {
	const response = await control.value?.reload({ force: true });
	result.value = response?.status ?? 'cancelled';
}
</script>

Data sources and overrides ​

Provide exactly one source: dataSource, api with params, or request. See the full notes.

Single selection uses a scalar or null in value mode and a normalized AsamOption in object mode. For multiple selections, combine multiple, valueMode, and multipleValueMode to choose an array or a delimited string. Object mode requires an array. Update the model type when changing the value strategy.

If the top-level multiple is omitted, props.multiple applies. An explicit top-level true or false takes precedence. Update the model when changing multiple selection. Source validation and the display control use the same effective setting.

Clearing an object-mode single selection publishes null. A valid native valueOnClear of false or 0 also preserves update:modelValue, change, and clear when emptyValues contains that value. See the full notes.

Return the entire hierarchy in one response. The field mapping normalizes children. The data contract reads a complete tree and excludes lazy, load, props.lazy, and props.lazyLoad. The model uses ASAM scalar or object mode.

Lifecycle, events, and instance methods ​

active=false pauses requests and retains the last successful data. Use reload({ force: true }) for fresh data and cancel() to cancel the current request. See the full notes.

immediate controls the initial request, and active controls whether requests are enabled. See the generated API for the defaults and their sources.

Slots and base features ​

The default slot keeps the Cascader or Tree Select node scope with data, node, and an optional option. See the linked base component and this page's public slots for scopes such as tag and label.

Related base components ​

  • Cascader provides the applicable display, interaction, and public API.

Use this page's rules for data sources, models, events, and exposed members, and refer to the linked base components for the features available here. Sizes follow the ASAM base components. Examples use default.

Complete tree and multiple selection in object mode ​

The example returns the full organization tree in one response. multiple and valueMode="object" store normalized options with their original members in raw. Disabled members are unavailable for selection. See the full notes.

The example records each update:modelValue, change, success, and error payload. Model and success snapshots include normalized options and the original raw tree. Error snapshots include the error kind and message. See the full notes.

defineOptions({ name: 'AsamRemoteCascaderCompleteTreeDemo' });
import { ref } from 'vue';
import { AsamCheckboxItem, AsamButton, AsamRemoteCascader, defineAsamOptions } from '@asam-ui/ui';
import type {
	AsamCascaderDataEmits,
	AsamValue,
	AsamDataError,
	AsamRemoteCascaderExpose,
	AsamOption,
	AsamApiRequest
} from '@asam-ui/ui';
import type { Member } from './provider.js';
import { members } from './provider.js';
const active = ref(true);
const failure = ref(false);
const slow = ref(false);
const api: AsamApiRequest<undefined, readonly Member[]> = async (_params, context) => {
	await new Promise<void>((done) => setTimeout(done, slow.value ? 500 : 100));
	context.signal.throwIfAborted();
	if (failure.value) throw new Error('演示完整树请求失败');
	return members;
};
const dataSource = defineAsamOptions<string, Member>().api({
	api,
	params: undefined,
	transform: (response) => response,
	fieldNames: { label: 'label', value: 'value', children: 'children', disabled: 'disabled' }
});
const value = ref<readonly AsamOption<string, Member>[]>([]);
const control = ref<AsamRemoteCascaderExpose<string, Member>>();
const result = ref('');
const successes = ref(0);
const error = ref('');
const checkedCount = ref(0);
type DataEmits = AsamCascaderDataEmits<AsamValue, object>;
const events = ref<readonly { readonly name: string; readonly payload: unknown }[]>([]);
function recordEvent(name: string, payload: unknown) {
	const snapshot: unknown = JSON.parse(JSON.stringify(payload));
	events.value = [...events.value, { name, payload: snapshot }];
}
function onModelUpdate(payload: DataEmits['update:modelValue'][0]) {
	recordEvent('update:modelValue', payload);
}
function onModelChange(payload: DataEmits['change'][0]) {
	recordEvent('change', payload);
}
function onSuccess(payload: DataEmits['success'][0]) {
	recordEvent('success', payload);
	successes.value++;
	error.value = '';
}
function onError(payload: AsamDataError) {
	recordEvent('error', { kind: payload.kind, message: payload.message });
	error.value = payload.message;
}
async function reload() {
	result.value = (await control.value?.reload({ force: true }))?.status ?? 'cancelled';
}
async function cancelSlow() {
	slow.value = true;
	const pending = control.value?.reload({ force: true });
	setTimeout(() => control.value?.cancel(), 30);
	result.value = (await pending)?.status ?? 'cancelled';
	slow.value = false;
}
function inspect() {
	checkedCount.value = control.value?.getCheckedNodes(false)?.length ?? 0;
}
</script>

Native events on the data component ​

Cascader forwards the native visibleChange, expandChange, and removeTag events. Tree drag and drop, check, popup-scroll, and end-reached are outside this event interface. The data wrapper adds success and error and applies this page's value and object modes to model events.

Local request error slot ​

The optional error slot runs only when the current request has an error. It receives a read-only { error, stale, retry } scope. See the full notes.

Call retry() without arguments. It returns the forced reload Promise and follows the same cancellation and unmount behavior. See the full notes.

Providing the slot replaces the default local error region, including when the slot renders empty content. With the slot omitted, the component displays its error message, stale-data hint, and retry button. The slot requires a current error. empty, loading, and other base slots keep their original scopes.

In the complete TypeScript and JavaScript example, trigger a failure and await the slot's retry() result. After a success, trigger a refresh failure to see the existing result and model retained. Each mount creates an isolated child app with a local provider.

import type { AsamDataProvider } from '@asam-ui/ui';
export interface Item {
	readonly id: number;
	readonly value: string;
	readonly label: string;
}
export function createTransport() {
	const failing = ref(true),
		calls = ref(0),
		refreshes = ref(0);
	const api = async () => {
		calls.value++;
		if (failing.value) throw Error('演示请求暂不可用');
		return [
			{ id: 1, value: 'ready', label: '准备' },
			{ id: 2, value: 'running', label: '进行' }
		] satisfies readonly Item[];
	};
	const provider: AsamDataProvider = {
		dict: {
			get: async (
				_type: string,
				context: Parameters<NonNullable<AsamDataProvider['dict']>['get']>[1]
			) => {
				context.signal.throwIfAborted();
				return api();
			},
			refresh: async (context) => {
				context.signal.throwIfAborted();
				refreshes.value++;
			}
		}
	};
	return { failing, calls, refreshes, api, provider };
}
export type Transport = ReturnType<typeof createTransport>;

Additional usage notes ​

Data sources and overrides ​

Provide exactly one source: dataSource, api with params, or request. Create a dataSource with defineAsamOptions and configure mapping, transformation, and caching inside the factory. Use the top-level shorthand props only for the shorthand branches. Custom field mapping requires a synchronous transform. The API returns a Promise and checks context.signal.

Data sources and overrides ​

Clearing a single object selection publishes null. Valid native clear values such as false or 0 preserve update:modelValue, change, and clear when included in emptyValues. Clearing multiple selections publishes an empty array. A clear factory that returns [] or [null] also publishes null for single objects when the matching array is included in emptyValues. Business options with 0 or false retain their full normalized AsamOption and raw. Their native instance keys are number:0 and boolean:false, distinct from native clear values.

Lifecycle, events, and instance methods ​

active=false pauses requests and retains the last successful data. Use reload({ force: true }) for fresh data and cancel() to cancel the current request. success emits a normalized option array. error emits an AsamDataError. A failed refresh marks the last successful data stale. Handle the reload result by its status of success, error, or cancelled.

Complete tree and multiple selection in object mode ​

The source returns the full organization tree. multiple with valueMode="object" stores normalized options and their original members in raw. Disabled members are unavailable. The example shows node rendering, header and footer, filtering, clearing, native getCheckedNodes(), a failed refresh that retains previous data, and slow-request cancellation. It records only the checked-node count to avoid serializing cyclic node references. The API runs locally, receives an AbortSignal, and checks for cancellation. The source supplies the whole tree up front.

Complete tree and multiple selection in object mode ​

The example records update:modelValue, change, success, and error payloads individually. The model and success results preserve the normalized objects and original raw tree, and errors preserve kind and message. default reads normalized option.raw and native data.label. header and footer render content directly. Cancellation emits no extra success, and a failed refresh preserves the caller's model.

Hierarchy presentation and check strategy ​

The complete tree preserves disabled nodes and uses a raw string array model. The default slot reads native data and node and normalized option.raw. Collapsed tags display their tooltip. A custom tag uses native deleteTag, and removeTag forwards the base event payload unchanged. The model retains raw scalar values. A disabled control blocks deleting and checking. checkStrictly controls parent selection independently of descendants. Read checked node keys without serializing cyclic nodes. For native methods and events, get the key from data.value in default or a node's value from getCheckedNodes(false). Read business values from v-model or option.value. showCheckedStrategy chooses parent or child tags. virtualScroll renders a window into the preloaded subtree for large groups. fitInputWidth applies to the filtered search panel. A number fixes its width, true matches the input, and false uses its natural width with the input width as a minimum. The regular multi-column panel has its own width. Enter the member search term and switch among the three settings. suggestion-item customizes matching results. Virtual rendering uses the existing tree without per-node requests.

Hierarchy presentation and check strategy ​

The example sets height=180, itemSize=30, and fitInputWidth=360. height goes to the native virtual list. In the pinned 2.14.7 styles, 6px margins above and below, minimum height, and parent stretching yield a 192px viewport in this demo. The prop configures the list and outer panel styles still apply. With virtual scrolling on, only the visible window of the 200 children renders. Turning it off renders every child.

Local request error slot ​

The optional error slot runs only while the current request has an error. It receives a read-only { error, stale, retry } scope. The error is the same AsamDataError emitted by that instance, including cause, kind, message, and notified. Rendering the slot leaves the provider's notification state unchanged. stale indicates that the retained data is outdated.

Additional props and events ​

Local request error slot ​

Call retry() without arguments. It returns the Promise from reload({ force: true }) with the success, error, or cancelled branch of AsamReloadResult<readonly AsamOption<V, I>[]>. Retrying follows active, the current source, cancellation, and unmount, and preserves the model.
