Transfer ​

Example data, control text, messages and source comments may be in Chinese. Viewer controls and API headings use English. Untranslated API descriptions are marked.

Interactive examples, TypeScript and JavaScript source, and the generated API reference are included on this page.

When to use it ​

Move static options between two lists. The model contains selected values on the right. Normalized modes consume options; native mode uses raw data.

Moving, filtering and direction events ​

change supplies the latest value, direction and moved values, in that order. filterable enables searches on both sides. titles / buttonTexts set headings and action text.

String and object storage ​

Transfer always supports multiple selection; no multiple prop is needed. String storage uses separator. Object mode stores a normalized option array. targetOrder determines right-side order.

Use valueMode="native" with data and props to map raw key, label and disabled fields. The model is an array of raw keys.

Sizes and inheritance ​

The four examples explicitly use large, big, default and small. Omitted sizes respond to ConfigProvider; explicit sizes override ancestors. Do not invent a size prop for panels without a size contract.

ASAM extensions and migration ​

Four densities inherit through ConfigProvider and forms. ASAM value/object and array/string modes follow the shared storage rules; native mode preserves raw data behavior. Public exposes are clearQuery, leftPanel and rightPanel. Footer and empty slots are provided separately for each side.

Virtual scrolling and edge items ​

virtualScroll enables both virtual lists; itemSize is the actual virtual row height. Filtering and moving selected items to the right preserve the complete model. filterMethod(query, item) customizes matching; renderContent or the default slot customizes rows. Left/right footer and empty slots are independent. Default checked states, check-change events and targetOrder follow the same rules in virtual and ordinary lists. clearQuery('left'/'right') clears that search without changing the right-side selection model.

Rendering callbacks, initial checks and empty content ​

renderContent renders raw items using the supplied h; the default slot is an alternative, mutually exclusive rendering path. leftDefaultChecked / rightDefaultChecked initialize checked states only, without changing the model. format displays checked counts; change returns direction and raw moved keys. leftEmpty / rightEmpty provide empty content. Native mode disables each row through data.disabled; the example disables all rows by changing data. Whole-control disabled is an ASAM addition for advanced value/object modes only.

Try custom rendering.

In verified inputs using dependency 2.14.7 / Vue 3.5.34, adding a missing left-footer or right-footer slot dynamically after the first mount did not display new content. Native Transfer and ASAM native behaved identically. Fresh instances supplied with the respective slot at mount did display it. Declare footer slots initially; later additions are not guaranteed visible. Replacement, removal and other slots, including default and empty, have separate verification results.

Reading the API ​

Advanced modes default to Chinese titles meaning “Unselected / Selected”, empty button text and targetOrder="push". Native mode uses the underlying titles and ordering defaults. Explicit titles and buttonTexts override defaults. original follows source data/options order, push appends new items after existing right-side items, and unshift inserts them before. All preserve original keys and the selected value mode.

The reference is generated from current public types and runtime defaults. Combined props apply by branch; unknown or undeclared defaults do not mean false or empty. Standalone Demo.vue files inline local helpers, data and assets.

Native and advanced entries ​

valueMode="native" delegates directly and preserves omitted titles, buttonTexts, targetOrder, modelValue and native defaults. Its default slot receives only { option }; advanced value/object paths provide { option, data }. left-check-change / right-check-change retain the second argument, including undefined. change preserves value, direction and moved values in their original order. clearQuery preserves the native return value; leftPanel / rightPanel read live references.

Native mode adds no independent disabled contract. Advanced disabling, object/string models and form validation belong to ASAM composition. Virtual-list height and cache timing after moves follow native behavior; ASAM does not patch VNodes or internal setup.
