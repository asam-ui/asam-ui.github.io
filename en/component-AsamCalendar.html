Usage guidelines ​

Bind a Date with v-model. Use range to limit the displayed range and controllerType and formatter to configure the controls and their formatting. The date-cell slot receives data. See the API for the header slot and instance methods such as selectDate. The application supplies any schedule data.

Complete examples from 2.14.7 ​

These examples adapt the Element Plus 2.14.7 calendar examples to use public ASAM components and icons. Both the TypeScript and JavaScript versions run independently. Calendar uses a Date model. In examples that use DatePicker, an explicit empty valueFormat preserves the upstream Date model, while ASAM DatePicker defaults to formatted date text.

Localization and advanced configuration ​

Toggle Chinese and English with AsamConfigProvider and configure the calendar through the public AsamCalendarProps type. The model and date range follow the Calendar API. The example sets controllerType to select and supplies a formatter for the month and year labels.

Date localization and control labels are configured separately. The example's locale.ts and locale.js files also register the Day.js zh-cn locale. The week starts on Monday in Chinese and on Sunday in English. See the full notes.

import dayjs from 'dayjs';

interface LocaleSelection {
	locale: string;
	order: number;
}
interface LocaleSession {
	baseline: string;
	lastWritten: string;
	sequence: number;
	selections: Map<symbol, LocaleSelection>;
}
declare global {
	// Application example state is shared by TS/JS copies, keyed by the public Day.js object.
	var asamCalendarAdvancedExampleLocalesV1: WeakMap<typeof dayjs, LocaleSession> | undefined;
}

/** Own only the example's global date-locale changes; no native instance or private API. */
export function createCalendarDateLocaleSession() {
	const sessions = (globalThis.asamCalendarAdvancedExampleLocalesV1 ??= new WeakMap());
	let session = sessions.get(dayjs);
	if (!session) {
		const baseline = dayjs.locale();
		session = { baseline, lastWritten: baseline, sequence: 0, selections: new Map() };
		sessions.set(dayjs, session);
	}
	const state = session;
	const token = Symbol('calendar-example');
	let released = false;
	const observeExternalLocale = () => {
		const current = dayjs.locale();
		if (current !== state.lastWritten) state.baseline = current;
	};
	const write = (locale: string) => {
		state.lastWritten = dayjs.locale(locale);
	};
	return {
		select(locale: 'zh-cn' | 'en') {
			if (released) return;
			observeExternalLocale();
			state.selections.set(token, { locale, order: ++state.sequence });
			write(locale);
		},
		release() {
			if (released) return;
			released = true;
			observeExternalLocale();
			state.selections.delete(token);
			const remaining = [...state.selections.values()].sort((a, b) => b.order - a.order)[0];
			write(remaining?.locale ?? state.baseline);
			if (!state.selections.size) sessions.delete(dayjs);
		}
	};
}

import dayjs from 'dayjs';
/** Own only the example's global date-locale changes; no native instance or private API. */
export function createCalendarDateLocaleSession() {
	const sessions = (globalThis.asamCalendarAdvancedExampleLocalesV1 ??= new WeakMap());
	let session = sessions.get(dayjs);
	if (!session) {
		const baseline = dayjs.locale();
		session = { baseline, lastWritten: baseline, sequence: 0, selections: new Map() };
		sessions.set(dayjs, session);
	}
	const state = session;
	const token = Symbol('calendar-example');
	let released = false;
	const observeExternalLocale = () => {
		const current = dayjs.locale();
		if (current !== state.lastWritten) state.baseline = current;
	};
	const write = (locale) => {
		state.lastWritten = dayjs.locale(locale);
	};
	return {
		select(locale) {
			if (released) return;
			observeExternalLocale();
			state.selections.set(token, { locale, order: ++state.sequence });
			write(locale);
		},
		release() {
			if (released) return;
			released = true;
			observeExternalLocale();
			state.selections.delete(token);
			const remaining = [...state.selections.values()].sort((a, b) => b.order - a.order)[0];
			write(remaining?.locale ?? state.baseline);
			if (!state.selections.size) sessions.delete(dayjs);
		}
	};
}

Additional usage and API notes ​

Localization and advanced configuration ​

Date localization and control labels are configured separately. The example's locale.ts and locale.js files register the Day.js zh-cn locale. The week starts on Monday in Chinese and on Sunday in English. Explicitly install dayjs in the application and ensure the application and Calendar share the same instance.

Registering a Day.js locale makes it available for selection. Calendar in this version reads the global Day.js locale for the week start when it creates the date table. The example switches both the reactive provider locale and the global Day.js locale, uses a Vue key to recreate the table, and manages the shared locale through date-locale-session.ts or date-locale-session.js.

When several examples are mounted, the most recently selected locale becomes the global locale. When the last example unmounts, the helper restores the locale from before the first example mounted, regardless of unmount order. TypeScript and JavaScript copies share the same session, and repeated release calls are safe. The helper uses an observed external locale write as the new value to restore. Coordinate locale changes across the application because the global setting affects every consumer that shares its Day.js instance.
